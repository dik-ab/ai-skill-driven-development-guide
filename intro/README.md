# 入門編: AIDLC を理解するための最短コース

このフォルダは、社内発表向けに「AI 駆動開発の考え方」と「AIDLC（AI Development Life Cycle）」を最短で理解するための入門編です。
親フォルダの 01〜12 章は詳細なリファレンスです。入門編を読んでから必要な章だけ開いてください。

## 対象読者

- AI コーディングツール（Claude Code など）を触ったことはあるが、チームで運用したことはない人
- 「AI に任せると、動くけれど仕様と違うものができる」経験がある人
- 設計書や業務ルールはあるが、AI との結び付け方が分からない人

前提知識は「Git と PR を使った開発経験」だけです。DDD や CQRS の知識は不要です。

## 発表で使う場合

30 分の発表なら、次の構成を推奨します。

1. `01-why.md` の「AI がズレる 5 つの型」で問題を共有する（5 分）
2. `02-skills.md` の「3 層の表」と図書館の比喩で仕組みを 1 枚にする（5 分）
3. `03-spec-driven.md` と `04-auto-review.md` を各 1 枚ずつ（5 分）
4. `05-aidlc.md` の「5 フェーズの表」と「重さを変える」を説明する（8 分）
5. `06-aidlc-example.md` を実況する（5 分）
6. `07-getting-started.md` の「明日からやる 1 つ」で締める（2 分）

## 書き方の方針

- 用語は日本語を基本にし、初出でだけ英語を括弧書きする。例: スキル（skill）
- ファイル名とコマンドだけは原文のまま書く。例: `CLAUDE.md`
- 例は架空の「会議室予約アプリ」で統一する。特定の業種や案件の知識は不要
- 各章の冒頭に「この章で分かること」を 3 行で置く
